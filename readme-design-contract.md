# README Design Contract

## readmeArchetype
Inspection field manual and chain-of-custody dossier. The README reads like the
operating manual an inspector carries: numbered protocols, evidence-log framing,
and before/after comparison. This differs from persona-seal's consent charter
(preamble plus Articles and Annexes) and from every other registry entry
(operator runbook, annotated dialogue, gazetteer, codex, man-page, parlor
rulebook, lab notebook, incident debrief, tide almanac, baton document).

## readmeNarrativeVoice
Plain, procedural, field-inspector voice. Numbered protocols and logged
observations, the way a condition report is written to be read by both a landlord
and an engineer. No marketing hype, no breathless tone, no legal-charter cadence.

## readmeSectionPattern
Field note (what MoveMark is and the dispute it settles) ->
Protocol 0: Why condition disputes are semantic (why GenLayer is essential) ->
Protocol 1: The record (contract state model) ->
Protocol 2: Capturing the condition (write methods and what they mutate) ->
Protocol 3: The adjudication gate (consensus question and the seven outcomes) ->
Protocol 4: Powers reserved to code (deterministic guards and backstops) ->
Protocol 5: Validators of record (the six checks and what each rejects) ->
Protocol 6: Reading the record (view methods) ->
Protocol 7: The instrument panel (frontend architecture, visual and motion system) ->
Protocol 8: Field setup (local setup as numbered steps) ->
Protocol 9: Conformance log (testing instructions) ->
Protocol 10: Deployment notes ->
Evidence locker (on-chain coordinates, pending placeholders) ->
Safety and legal notice (disclaimer).

This protocol-and-log order is not used by any prior registry README and avoids
the banned default skeleton.

## readmeMotif
Numbered protocols and an evidence log. Section headers read as Protocols;
reference material reads as the Evidence locker; key terms are defined once and
then used consistently (Condition Case, Snapshot, Claim, Gate, Settlement
Receipt). Before/after framing recurs: entry versus exit.

## requiredFactsPlacement
- Project identity and one-sentence description: Field note.
- Why condition disputes are semantic: Protocol 0.
- Why GenLayer is essential: Protocol 0 and Protocol 3.
- Contract state model: Protocol 1.
- Write methods and what they mutate: Protocol 2.
- Consensus question: Protocol 3.
- The seven outcomes: Protocol 3.
- Deterministic guards before AI: Protocol 4.
- Deterministic backstops after consensus: Protocol 4.
- Validator substance and what is rejected: Protocol 5.
- View methods: Protocol 6.
- Frontend architecture, visual and motion system: Protocol 7.
- Local setup: Protocol 8.
- Testing instructions: Protocol 9.
- Deployment notes: Protocol 10 and the Evidence locker.
- Live contract address and frontend URL: Evidence locker (marked pending).
- Safety and legal disclaimer: Safety and legal notice.

## bannedReadmePatterns
- The banned default heading skeleton (What it is / Why GenLayer is essential /
  Contract mechanic / ... / Known limitations).
- The persona-seal consent-charter shape (Preamble plus Articles and Annexes).
- Opening with a marketing paragraph or a badge row.
- A three-column footer or feature-card grid rendered in prose.

## proofOfDifference
Versus persona-seal, whose README is a legal consent charter of Articles and
Annexes, MoveMark's README is an inspection field manual: numbered Protocols, an
evidence log, and before/after entry-versus-exit framing in a procedural
inspector voice. The document metaphor, section order, and voice are all distinct
from persona-seal and from every other registry entry.
